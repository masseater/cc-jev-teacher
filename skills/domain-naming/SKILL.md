# ドメインの言葉で名付ける

名前は、その業務に詳しい人が同じものを指すときに使う言葉にする。「データを受け取って処理する」のような仕組みの説明は、中身を変えるたびに名前とずれ、業務の話とコードの話を突き合わせられなくなる。

HTTP・DB・CLI などの外部との接続や汎用のユーティリティは、仕組みそのものが扱う対象なので、この限りではない。

## 手順

1. プロジェクトの用語集を探す。無ければ README や既存のコードから、業務の言葉として使われている語を拾う。
2. 名付ける対象が業務で何を表すかを一文で言う。言えないなら、まだ概念が決まっていないので、先に利用者に確かめる。
3. その一文の主語や目的語を名前にする。用語集の語があればそれを使い、同じものに別の語を当てない。
4. 新しい概念なら用語集に足す。用語集の作り方と保ち方は mattpocock/skills リポジトリの domain-modeling スキルに従う。
5. 名前を見直すときは、[references/smells.md](references/smells.md) の兆候を手がかりに、仕組みで名付けたものを探す。
