# 全てを計測せよ


## コード: 失敗を消さない

- 失敗したときの処理は次のどれかにし、どれでもログを残す
  - タグ付きエラーとして呼び出し側へ返す
  - WARN 以上でログを出してから投げ直す
  - ログを出してから名前の付いた縮退状態（`"unavailable"` など）を返し、呼び出し側と画面がそれを扱う
- 禁止: `Effect.orElseSucceed` / `Effect.catch` / `Effect.ignore` / `.catch(() => 既定値)` / `?? 既定値` で、失敗をログ無しに成功や空の値へ変えること
- ログには `_tag`・`message`・元の例外の `name` と `message`・所要時間・対象（ルート、外部サービス名）を入れる
- ブラウザ側では Eden の `error` を捨てない
  - React Query の中なら投げ直して `QueryCache` / `MutationCache` に報告させる。`useMutation` には `mutationKey` を付ける
  - 通信の失敗を、入力の誤りと同じ表示にしない
- タイムアウトとリトライは値を明示し、打ち切りとやり直しをログに出す
- 縮退状態は画面にも出す。黙って止めず、エラーの一文と再試行ボタンを置く
- 触ったコードに握りつぶしがあれば、同じ作業で直す。直さないなら、何を隠しているかを報告に書く

## コード: 計測できていることを確かめる

ログ・計測を足した・直したら、出ていることを実際に引いて確かめるまで完了にしない。

- 失敗したときの処理を足した・直したら、dev で実際に失敗させる（外部呼び出しを落とす、タイムアウトを極端に短くするなど）
- 成功した場合も dev で 1 回動かす
  - ソースを読まずに原因が分かる
  - `_tag`・`message`・所要時間・対象・level が空でなく入っている
  - 動かした回数と、引けたログの件数が一致する
- 引けなかった・項目が欠けていたら、ログを出す側を直して、もう一度引く

## 調査: 期間・分母・分子をそろえる

- 数える前に、対象がそのログに記録されていることを確かめる。調べたい操作を dev で 1 回起こし、そのログが引けることを見てから数える
- 0 件だったら、本当に 0 件なのか、記録されていないだけなのかを、上の方法で確かめてから報告する

- 頻度は、期間・分母（対象の全リクエスト数）・分子（失敗数）をそろえて出す
- レイテンシは p50 / p90 / p99 / 最大と件数で出す
- ログの保持範囲を確かめる。AI Gateway のように件数で古いものが消えるログは、実際に見られた期間を併記する
- 取得件数が `limit` に達したら、ページを進めるか期間を分けて、全件取り切る

## 調査: 取れなかったものを隠さない

- 失敗・空・想定外の形が返ったら先へ進まず、エラー本文を読んで取り直す
- 取り直せなかったものは、「取れなかった」と理由付きで報告する。取れた一部だけで全体を語らない
- 観測した事実と推測を分けて書く。推測には、次に何で確かめるかを添える
- 「直った」は、直す前の条件を dev で再現し、直した後に同じ条件で結果が変わったのを見てから言う
