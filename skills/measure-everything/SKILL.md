# 全てを計測せよ


## コード: 失敗を消さない

- 失敗経路は次のどれかにし、どれでもログを残す
  - タグ付きエラーとして呼び出し側へ返す
  - WARN 以上でログを出してから投げ直す
  - ログを出してから名前の付いた縮退状態（`"unavailable"` など）を返し、呼び出し側と画面がそれを扱う
- 禁止: `Effect.orElseSucceed` / `Effect.catch` / `Effect.ignore` / `.catch(() => 既定値)` / `?? 既定値` で、失敗をログ無しに成功や空の値へ変えること
- ログには `_tag`・`message`・元の例外の `name` と `message`・所要時間・対象（ルート、外部サービス名）を持たせる
- タイムアウトとリトライは値を明示し、打ち切り・やり直しをログに出す
- 縮退状態は画面にも出す。黙って止まらず、エラーの一文と再試行を置く
- 触ったコードに握りつぶしがあれば、同じ作業で直すか、何を隠しているかを報告に書く

## コード: 出したログを確かめる

- 失敗経路を足した・直したら、dev で実際に失敗させる（外部呼び出しを落とす、タイムアウトを極端に短くするなど）

## 調査: 分母・分子・期間を揃える

- 頻度は期間・分母（対象の全リクエスト数）・分子（失敗数）を揃えて出す
- レイテンシは p50 / p90 / p99 / 最大と件数で出す
- ログの保持範囲を確かめる。AI Gateway のように件数で切れるものは、実際に見られた期間を併記する
- 取得件数が `limit` に達したら、ページを進めるか期間を割って取り切る

## 調査: 取れなかったものを隠さない

- 失敗・空・想定外の形が返ったら先へ進まず、エラー本文を読んで取り直す
- 取り直せなかったものは「取れなかった」と理由付きで報告する。取れた一部で全体を語らない
- 観測した事実と推測を分ける。推測には、次に直接確かめる手段を添える
- 「直った」は、直す前の条件を dev で再現し、直した後に同じ条件で結果が変わったのを見てから言う
